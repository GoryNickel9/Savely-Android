# Confronto statico del dataset comune dei moduli

La parte statica di questa revisione confronta input già presenti nelle fixture con le formule e i payload dei sorgenti. È stata redatta senza eseguire test, calcoli, build, emulatori, script, API o operazioni backend. Le attese delle tabelle sono quelle letterali delle fixture esistenti o dei rami espliciti del codice. Nessun caso riceve uno stato PASS da questa lettura. Una successiva verifica offline autorizzata dell'oracolo web è riportata in una sezione separata, con il suo ambito.

Riferimenti della revisione richiesta: web `1cfcf6297e85d56bfafe3522362ceecef6f6b281`; Android `614bdbf`, core `935c7ba`. Data del dataset numerico FIRE: anno 2026, come nella fixture conservata. I test Android che usano l'anno corrente devono sostituire solo l'anno, mantenendo giorno, mese e importi. I dati descritti sono sintetici; `owner` e `foreign-owner` indicano account fixture, senza credenziali.

Le classificazioni hanno un ambito preciso: **uguale** indica la stessa formula o semantica per quel caso; **differenza intenzionale** indica una scelta nativa esplicita di validazione, isolamento o rappresentazione; **esterno non verificato** riguarda un contratto che dipende da un servizio. Una divergenza di presentazione non ancora deliberata resta un punto aperto separato.

Il ritorno reale usato per il tempo al target è `(1 + rendimento) / (1 + inflazione) - 1`; la proiezione del portafoglio usa invece il rendimento nominale e mostra a parte il valore reale. La persistenza è una **differenza intenzionale**: il web usa la chiave globale browser `fire-calc-params`; Android usa preferenze per account e preserva gli snapshot corrotti finché l'utente sceglie il reset. Il link web applica parametri URL; Android richiede incolla, anteprima e applicazione esplicita. [FireSharingScreenTest.kt](../app/src/androidTest/java/cc/savely/android/modules/FireSharingScreenTest.kt), righe 87–149, definisce tutti i dieci parametri, account estraneo invariato e zero HTTP. La presentazione degli importi FIRE differisce: `calculations.ts:189` usa EUR senza cifre decimali; `ModuleScreen.kt:45` usa il formatter EUR italiano con due cifre. Il numero sottostante dei casi precedenti è lo stesso; questa revisione non certifica equivalenza pixel o stringa.
